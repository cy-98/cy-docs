# 从助手到团队：Agent 在工作中的角色演变

找到「如何尽可能使用 AI 替代日常工作」这个问题的答案之前，先回顾 Agent 在我工作里换过几次身份。

```
助手  ──▶  码农    ──▶  工程师    ──▶  团队
问答       写代码       独立干活       端到端交付
```

## 助手

24 年初，ChatGPT 进了团队。大家特别震惊：不用预先编程，对不特定的输入也能贴切地回答。

工作还是人做。

## 码农

同年 Cursor 和 GitHub Copilot 进入视野，能快速补全，「Tab 工程师」这个戏称开始流传。

之后 Cursor 能基于工程理解写代码。，根据**特定目标**完成代码的编写。

再往后是 Custom Agent、Plan mode、Agent Review。编辑器里的 Agent 越来越好用，效率也确实上去了。

人还停留在编辑器里，Agent 是更快的手。

## 工程师

MCP、Skill、A2A 出现后，Agent 开始进日常工作：读文档、设计图和流程图、搜代码、编码和部署。

它已经能独立完成一件活，但上下文有限，往往需要人中途介入决策。

Agent 跳出了编码的职责，能够触及更大的工作范围。

## 团队

25 年初公司开始用 Claude Code。和 Cursor 最大的不同：Terminal UI 代替了编辑器。极简交互、丰富命令，加上当时够好的 Sonnet，大家很快把手里的 Cursor 换掉了。

Terminal Agent 弱化了代码文件的存在感，任务靠持续对话完成。「Vibe coding」流行起来，社区对 Agent orchestration 也越来越热。流行的 Sub Agent，Team mode，多 session 并行让 vibe coding 氛围浓厚了起来。

到 26 年，工具集成已经很成熟。几乎一句话，Agent 就能持续写代码、提 MR、部署测试环境、做端到端验证。人等着审查和合并。

人变成了决策者， Agent 是一个团队。

## 结语

四个身份，对应同一件事：Agent 能接管的环节变长了，人留下的环节变短了、也更重了。

| 角色 | Agent | 人 |
| --- | --- | --- |
| 助手 | 问答、给片段 | 几乎全部交付 |
| 码农 | 按目标写代码 | 设计代码，等着实现 |
| 工程师 | 独立完成一件活 | 定义上下文和计划，等待 review 结果|
| 团队 | 写、提 MR、部署、验证 | 审查、合并、担责 |

下一篇写的是：人还该做哪三个决策，以及决策之外怎样全部 Agent 化。见 [如何尽可能使用 AI 替代日常工作](https://docs.page/cy-98/cy-docs/complete%20agentic)。
